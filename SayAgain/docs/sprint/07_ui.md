# Layer: UI

**Purpose.** One SwiftUI screen. No navigation, no tabs. Four buttons, one live text area, one dropdown, one export sheet.

## Screen layout

```
┌────────────────────────────────────────────────┐
│  Translate to: [ None ▾ ]              [↥]     │  ← top bar
├────────────────────────────────────────────────┤
│                                                │
│  [14:32:07] [de] Guten Tag, wie geht es dir?   │
│              Bonjour, comment allez-vous ?     │  ← translation, when target active
│                                                │
│  [14:32:14] [de] Ich wollte kurz sagen…        │
│                                                │
│  ich habe noch nicht█                          │  ← volatile: no timestamp, no lang tag
│                                                │
├────────────────────────────────────────────────┤
│   [ Clean ]      [ ● Start ]      [ Cancel ]   │  ← bottom bar
└────────────────────────────────────────────────┘
```

## Controls

### Start (round green button, centred, primary)

- Disabled state: not applicable — always tappable. If mic permission is not granted, tap triggers the request; on denial, an inline message appears where the button was ("Enable Microphone in Settings"). Sprint test 7.18.
- Tapping starts capture, transcription and (if a target is set) translation. Label becomes **Stop**; colour becomes red-orange. Sprint test 7.2.

### Stop (replaces Start when running — graceful drain)

- Signals `TranscriptionCoordinator.stop()`, which:
  1. finalises any pending volatile text as a `TranscriptLine`,
  2. drains the audio queue so the last utterance lands (sprint test 7.9),
  3. flushes translations for that final line,
  4. closes both sinks.
- Button returns to **Start**. The finalised transcript remains on screen and on disk. This is the normal end-of-session flow.

### Cancel (bottom-right — hard discard)

- Present whether recording or idle.
- Tap while recording: stops capture immediately, drops volatile line, calls `sink.discard()` and `translationCoordinator.discardAll()` — deletes `transcript.txt` and every `translate.<LANG>.txt`.
- Tap while idle: only acts if a previous session's files exist on disk; same discard behaviour. Otherwise no-op.
- Confirmation: **Yes** — one `.confirmationDialog` with "Discard this session? This deletes the transcript." Two taps to lose data is the invariant.

### Clean (bottom-left — wipe everything)

- Clears the on-screen finalised list, drops volatile, and calls `discardAll()` on both sinks (transcript + every translation file).
- If a recording is in progress, it is stopped hard (same as Cancel) *and then* the state is wiped.
- Confirmation dialog: "Clear the screen and delete the transcript? This cannot be undone."

**Cancel vs Clean.** Cancel is "abort what I'm doing right now". Clean is "reset the app to a fresh state" — the difference is whether the current session was ever meaningful. Same underlying discard, different intent.

### Translate to (top-left, `Picker` with `MenuPickerStyle`)

- First option: **None** (no translation; default). Sprint test 7.6.
- Remaining options: whatever `LanguageCatalog.availableTargets()` returned, in localised display-name order. Sprint tests 7.5, 4.13.
- Changing the selection mid-session is forward-only: existing on-screen lines do not re-translate; the next finalised line is translated to the new target. Sprint tests 7.7, 7.8, 4.11.

### Export (top-right, `↥` share icon)

- Sheet with three rows: **TXT**, **CSV**, ~~**DOCX**~~ (grayed out with "coming soon" in MVP).
- Also: **Copy full text** as a direct button — one tap. Sprint test 7.14.
- Choosing a format hands `[ExportedFile]` to `UIActivityViewController` via a `UIViewControllerRepresentable`. Sprint test 7.13.
- Above the format list, a small footnote in `.caption` style: *"Mail and Notes send your transcript off this device. Copy and Files stay on it."* This is the sprint's explicit requirement — the privacy claim is stated at the point of export. Sprint tests 7.16.
- Export while recording captures the session so far without stopping it. Sprint test 7.15.

## Live text behaviour

- One `List` / `ScrollView` for finalised lines. Each row: `[HH:mm:ss] [lang] text` and, when a target was active at finalisation, an indented translation line below.
- Below the list, **exactly one volatile row**, styled slightly muted, updated in place on every `.volatile` event. Sprint tests 7.3, 7.4.
- On `.final`, the volatile row is replaced (not appended) by the new finalised row. Sprint test 7.4 is the explicit "never appended twice" assertion.

## Accessibility (MVP — enough to pass Phase 7's identifier check)

Every interactive element carries an `accessibilityIdentifier`:

| Element | Identifier |
|---|---|
| Start / Stop button | `sayagain.button.record` |
| Cancel button | `sayagain.button.cancel` |
| Clean button | `sayagain.button.clean` |
| Translate-to picker | `sayagain.picker.target` |
| Export icon | `sayagain.button.export` |
| Volatile row | `sayagain.text.volatile` |
| Finalised list | `sayagain.list.transcript` |

Rule 7.17: **containers must call `.accessibilityElement(children: .contain)` *before* `.accessibilityIdentifier(...)`**. Order matters in SwiftUI's modifier stack.

## Composition

```swift
struct ContentView: View {
    @EnvironmentObject private var env: SessionEnvironment
    @StateObject private var vm: SessionViewModel   // wraps the two coordinators

    var body: some View {
        VStack(spacing: 0) {
            TopBar(vm: vm)
            TranscriptListView(vm: vm)
            BottomBar(vm: vm)
        }
    }
}

@MainActor
final class SessionViewModel: ObservableObject {
    @Published var finalisedLines: [TranscriptLine] = []
    @Published var volatileText: String = ""
    @Published var availableTargets: [TranslationLanguage] = []
    @Published var selectedTarget: TranslationLanguage? = nil
    @Published var isRecording: Bool = false
    @Published var micPermission: MicrophonePermissionStatus = .notDetermined
    // ...bindings to TranscriptionCoordinator + TranslationCoordinator streams
}
```

`SessionViewModel` owns the reactive glue. `ContentView` and its children are declarative sub-views with no framework calls.
